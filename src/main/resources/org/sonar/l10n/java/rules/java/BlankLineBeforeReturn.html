This rule enforces a blank line before return statements to improve code readability.

Why is this an issue?

Having a blank line before return statements helps visually separate the return logic from the preceding code, making the code flow clearer and easier to read.

Rules

  • If a method has more than one line of code, a blank line before the return statement is mandatory
  • Lambda expressions should NOT have a blank line before the return statement
  • If a block (e.g., if-else) has more than one line and contains a return statement, a blank line before the return is mandatory

Noncompliant Code Example

public String processData(String input) {
    String processed = input.trim().toLowerCase();
    validateInput(processed);
    return processed; // Missing blank line before return
}

// Lambda with unnecessary blank line
list.stream()
    .filter(x -> {
        doSomething(x);

        return x.isValid(); // Unnecessary blank line in lambda
    })

Compliant Solution

public String processData(String input) {
    String processed = input.trim().toLowerCase();
    validateInput(processed);

    return processed; // Proper blank line before return
}

// Lambda without blank line
list.stream()
    .filter(x -> {
        doSomething(x);
        return x.isValid(); // No blank line in lambda
    })

Exceptions

  • Single-line methods do not require blank lines before return
  • Lambda expressions should never have blank lines before return
  • Single-statement blocks do not require blank lines
